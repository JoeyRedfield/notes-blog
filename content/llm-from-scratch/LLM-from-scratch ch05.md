# 控制随机性的解码策略（Temperature, Top-k）

## 温度缩放

> 我们总是使用torch.argmax（也称为贪婪解码）来采样具有最高概率的词元作为下一个词元。为了生成更多样化的文本，可以用一个从概率分布（这里是大语言模型在每个词元生成步骤为每个词汇条目生成的概率分数）中采样的函数来取代argmax。
> 温度大于1会导致词元概率更加均匀分布，而小于1的温度将导致更加自信（更尖锐或更陡峭）的分布。

![[image 1027.png]]

## Top-k

```bash
logits
 →（temperature 调整分布形状）
 → probability distribution
 →（top-k / top-p 截断候选集合）
 → sampling
```

温度高的话生成文本更随意自由，温度低的话比较保守偏向于概率高的输出，而Top-k可以改善温度高的时候生成的文本更合理。

你原句可以升级为下面这一版（更“从零构建模型”的表述）：

> Temperature 用于控制概率分布的平滑程度，从而调节生成的随机性；Temperature 越高，分布越平，生成越多样但不稳定，Temperature 越低，分布越尖，生成越保守。
Top-k 则通过限制参与采样的候选 token 数量，直接裁剪低概率 token，从而控制生成质量。二者可以组合使用：在较高 Temperature 下配合 Top-k，可以在保持多样性的同时避免极低概率 token 被采样。

---

可以用一句话记住：

> Temperature 决定“怎么随机”，Top-k 决定“在哪随机”。

- Temperature：**概率如何分配**
- Top-k：**允许哪些 token 参与抽奖**

![[image 1028.png]]

在真实大模型系统中，常见组合是：

| 场景 | Temperature | Top-k / Top-p |
| --- | --- | --- |
| 事实问答 | 低（0.2~0.5） | 小 k 或 p |
| 创意写作 | 高（0.8~1.2） | 中等 k / p |
| 代码生成 | 低 | 严格 Top-k |
| 聊天模型 | 中 | Top-p（更常见） |

# 使用PyTorch加载和保存模型权重

> 尽管样例中使用的大语言模型和数据集都相对较小，但这足以表明预训练大语言模型代价高昂。因此，保存大语言模型的参数非常重要，这样就不必每次使用它时都重新运行训练。
> 像AdamW这样的自适应优化器可以为每个模型权重存储额外的参数。AdamW可以使用历史数据动态地调整每个模型参数的学习率。如果没有它，那么优化器就会重置，模型可能学习效果不佳，甚至无法正确收敛，这意味着模型将失去生成连贯文本的能力。可以使用torch.save保存模型和优化器的state_dict内容

# 5.6 小结（整理版）

1. **自回归文本生成方式**
大语言模型采用自回归方式生成文本，即在给定已有上下文的情况下，模型逐步预测并生成下一个词元，直到达到终止条件。
2. **贪婪解码（Greedy Decoding）**
在默认设置下，模型将输出的 logits 转换为概率分布，并在每一步选择概率最高的词元作为下一个输出，这种解码策略称为贪婪解码。该方法生成过程确定性强，但多样性较低。
3. **概率采样与温度缩放**
通过对输出概率分布进行采样，并引入温度参数进行缩放，可以在文本生成过程中调节随机性与多样性，从而在连贯性与创造性之间进行权衡。
4. **训练损失与模型评估**
在训练过程中，训练集损失和验证集损失是衡量模型学习效果的重要指标，可用于评估模型对语言模式的建模能力及其泛化性能。
5. **预训练的目标与过程**
大语言模型的预训练通过不断调整模型参数，使其在大规模文本数据上最小化训练损失，从而学习语言的统计规律和结构。
6. **标准训练循环**
大语言模型的训练遵循深度学习中的标准训练流程，通常使用交叉熵损失函数和 AdamW 优化器对模型参数进行更新。
7. **预训练权重的复用**
在大规模语料上从头预训练大语言模型需要大量计算资源和时间，因此在实践中常通过加载公开可用的预训练权重，作为自行大规模预训练的高效替代方案。
