# Agentic Coding 与专业知识的持久回报

Anthropic 官方研究报告（2026-06-16），基于 **~40 万次 Claude Code 交互会话**（2025 年 10 月至 2026 年 4 月，~23.5 万用户）的隐私保护分析，研究 Agentic Coding 的实际使用模式、人机协作分工和成功率的决定因素。

> 核心结论：**决定 Agentic Coding 成败的不是编程背景，而是领域专业知识。** 从初学到中级的提升最大，中级到专家的边际收益递减。

## 一、分工模式：人定方向，AI 定执行

研究通过决策归因分类器，将每次会话的决策分为两类：

| 决策类型 | 内容 | 主导方 |
|----------|------|--------|
| **规划决策**（Planning） | 做什么、选什么方案、什么算完成 | **人**（~70%） |
| **执行决策**（Execution） | 改哪些文件、写什么代码、用什么语言、跑什么命令 | **Claude**（~80%） |

在实践中，分工非常清晰：**人决定要建造什么，Agent 决定怎么建造。**

### 每次提示触发的工作量

- 典型会话约 4 个来回（用户发提示 → Claude 干活）
- 每个提示平均触发约 **10 个 Claude 动作**，极端情况可超 100 个
- Claude 每次平均输出约 **2,400 词**

当 Claude 接管更多规划决策（>80%）时，每次提示触发的动作最多（约 16 个）。当用户保持执行控制（>80% 执行决策）时，动作最少（约 8 个）。

**与你的关联**：这精确描述了你当前的 AI 辅助编程模式——你决定功能需求和架构方向，Claude 负责具体代码实现。这份研究从 40 万次会话的统计数据层面验证了这种模式的普遍性和有效性。

## 二、专业知识的五个层级

研究从每次会话中评估用户在该任务上的专业水平（task-specific，与职位无关），分为五级：

| 级别 | 表现特征 | 每次提示触发动作 | 输出量（词） |
|------|----------|:---:|:---:|
| **Novice**（初学） | 通用指令，无领域知识体现 | ~5 | ~600 |
| **Advanced Beginner** | 能给出方向性指引 | — | — |
| **Intermediate**（中级） | 能精确框定要求，会验证关键点 | — | — |
| **Advanced** | 深度参与决策，能纠正 Claude 的错误 | — | — |
| **Expert**（专家） | 展现深层代码库/环境知识，主动引导 Claude | ~12 | ~3,200 |

> 专家级用户每次提示让 Claude 干的活是初学者的 **2.4 倍**，输出是初学者的 **5.3 倍**。这个差距在所有工作类型和任务价值层级中都稳定存在。

**关键洞察**：专业水平不是职位高低，而是**任务相关的领域把握度**。一个没写过 Python 但能精确描述对账规则并发现 Claude 遗漏边界情况的会计师，在该任务上就是专家。

## 三、专长越高，成功率越高——但大部分收益来自"初学→中级"

### 成功率数据

| 级别 | 验证成功（最严格） | 至少部分成功 |
|------|:---:|:---:|
| Novice | 15% | 77% |
| Intermediate ~ Expert | 28-33% | 91-92% |

**最大的跃升发生在从初学到中级之间**。中级到专家的斜率明显变缓——**胜任就够用了，深度专长只多带来一点点额外收益。**

### 遇到困难时的恢复能力

当会话"撞墙"（出现错误、测试失败、多次重试、用户表达不满）：

| 级别 | 撞墙后仍验证成功 | 撞墙后放弃（零代码产出） |
|------|:---:|:---:|
| Novice | 4% | 19% |
| Intermediate+ | 12-15% | 5-7% |

**初学者的放弃率是其他人的 3-4 倍。** 专业知识的一部分价值在于**能把 Agent 从错误方向上拉回来**。

**与你的关联**：你现在处于什么层级？取决于具体任务——在 Java 后端业务开发上可能接近 Intermediate/Advanced，在 Python 脚本任务上可能是 Advanced Beginner/Intermediate。好消息是，**从中级到专家的边际收益不大**，你不需要成为某个领域的顶尖专家就能从 Claude Code 获取大部分价值。

## 四、职业背景不如领域专长重要

研究推断用户职业（映射到美国劳工统计局 SOC 分类），结论出乎意料：

- 软件相关职业的**验证成功率约 30%**，非软件职业约 **26%**（在产出代码的会话中为 34% vs 29%）
- **至少部分成功**：软件 89% vs 非软件 88%——差距仅 1 个百分点
- 十大职业群体在成功率上全都在软件工程师的 **7 个百分点以内**
- **管理职业的验证成功率最高**，略超软件工程职业

> "似乎编程 Agent 正在让编程背景对成功编程变得不那么重要。"

七个月间，两个群体的成功率都在提升，但差距既未扩大也未缩小。

**与你的关联**：这是对你职业路径最直接的数据背书。你作为即将进入制造业的软件工程师，核心竞争力不在于"会写代码"（AI 正在削平这个优势），而在于**理解制造业业务流程、能精确描述需求、能判断 Claude 产出的对错**——即领域专业知识。

## 五、七个月的变化趋势

### 工作模式结构变化（2025.10 → 2026.04）

| 工作类型 | 变化 |
|----------|------|
| **修复代码**（Fixing） | 33% → 19%（大幅下降） |
| **运维操作**（Operating） | 14% → 21% |
| **写作与数据分析** | ~10% → ~20%（翻倍） |

修复类工作的占比下降近一半，被更端到端的用法取代：部署运行代码、分析数据、撰写非代码文档。

### 任务价值上升

通过对比自由职业者市场价格估算，**平均会话价值在七个月内上升约 27%**。构建类上升 43%，运维类上升 34%，修复类上升 32%。

**与你的关联**：修复 bug 的比例在下降，说明 Claude Code 正在从"修修补补的工具"变成"端到端完成任务的 Agent"。这也意味着你的工作方式应该向**定义任务目标和约束**倾斜，而非关注具体实现步骤。

## 六、对你工作模式的启示

### 1. 你已经在正确的范式上

"人定方向、AI 定执行"不是偷懒，而是 40 万次会话验证过的**最优分工模式**。继续强化你当前的工作方式。

### 2. 领域知识是你的护城河

进入格力后，最值得投资的是**制造业业务理解**（WMS/WCS/MES 流程、仓储物流逻辑），而不是钻研更多编程语言。行业 know-how 才是让 Claude 在你手里比在别人手里产出更多的乘数。

### 3. "够用就好"原则

中级水平就能获取大部分 AI 协作收益。对于 Python 学习，目标是能达到 Intermediate（能精确框定任务、能验证 AI 产出质量），而非 Expert（能独立手写复杂系统）。[[前20小时学会任何技能|20 小时快速学习]]的方法在这里完全适用。

### 4. 遇到困难时，不要放弃

初学者放弃率是其他人的 3-4 倍。当 Claude 撞墙时——记住这是正常现象，换一种方式描述需求、拆解任务、或让 Claude 自己分析错误，往往能恢复。你在 [[AI编码实践/inbound-order-实战记录|入库单实战]] 中经历的多轮调试就是这个道理。

### 5. 把你的管理能力用起来

管理职业的成功率最高——清晰的任务拆解、明确的验收标准、有效的反馈循环，这些"管理技能"在指挥 Agent 时比纯技术能力更有价值。[[Agent与自动化/AI Harness（驾驭层）知识手册|Harness Engineering]] 的核心理念与此一致。

> [!note]- 延伸阅读：研究方法论细节
>
> ### 隐私保护分析（Clio）
>
> 所有分析通过 Anthropic 的 Clio 隐私保护工具完成。无研究人员阅读原始会话记录，职业标签永不对应到可识别用户，只观察满足最低用户数的聚合数据。
>
> ### 九种工作模式分类
>
> 1. **构建**（Building）：新建功能/项目
> 2. **修复**（Fixing）：修 bug、解决问题
> 3. **测试/编排**（Testing/Orchestrating）：测试代码、编排 Agent 或流水线
> 4. **运维操作**（Operating）：部署、配置、运行流水线、监控系统
> 5. **理解**（Understanding）：学习现有系统
> 6. **规划**（Planning）：动手前的方案设计
> 7. **数据分析**（Analyzing）：数据处理与分析
> 8. **沟通**（Communicating）：写文档、演示文稿等
>
> ### 成功判断标准
>
> - **判定成功**（Judged Success）：分类器读完整会话记录，判断用户是否完成了目标
> - **验证成功**（Verified Success）：判定成功 + 至少一个硬信号（git commit/PR、测试通过、用户明确确认）
> - **失败信号**：错误、测试失败、重试、用户对产出不满
> - **放弃**（Abandoned）：失败 + 零代码产出
>
> ### 局限
>
> - 无法测量真实世界结果（代码是否实际被使用）
> - 排除了非交互式使用（headless 模式、IDE 插件、SDK）
> - 所有分类依赖模型读取会话记录，虽与遥测数据高度一致但难以大规模验证
> - 任务价值估算基于自由职业市场价格对比，精确度有限，主要用于相对比较
