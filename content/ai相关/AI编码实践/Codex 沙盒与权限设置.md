# Codex 沙盒与权限设置

> 这篇笔记整理一次关于 Codex 沙盒、批准策略、对话框权限选项的问答。核心问题是：**配置页里的沙盒设置，和对话框里的“请求批准 / 替我批准 / 完全访问”到底是什么关系。**

## 结论先行

- `sandbox` 不是把你的电脑或项目复制成一个假环境，而是限制 Codex 这个执行进程能对本机和工作区做什么。
- 工作区是真实的本地目录；沙盒是 Codex 访问它时的权限边界。
- 配置页里的「沙盒设置」更像默认安全边界。
- 对话框里的权限选择是当前会话的运行 preset，可以覆盖默认沙盒设置。
- 「替我批准」不是完全访问，它只是把越界请求交给自动审查器判断。
- 「完全访问」通常等价于 `danger-full-access` + `approval_policy = never`，风险最高。

## 一、沙盒到底是什么

更准确的理解是：

> 不是“你的本机 / 工作区本身变成了沙盒”，而是 **Codex 在访问你的本机 / 工作区时，被放进一个受限制的执行边界里**。

几个对象要分开：

| 对象 | 含义 |
| --- | --- |
| 本机 | 你的真实电脑，不是云端副本，也不一定是虚拟机 |
| 工作区 | Codex 当前主要被允许读取、编辑、运行命令的目录范围 |
| 沙盒 | 限制 Codex 对本机、工作区、命令、网络能做什么的权限边界 |

所以可以简化理解为：

> 对 Codex 来说，工作区是它主要活动的范围；沙盒设置决定它在这个范围内能做多少事，以及能不能越界。

## 二、常见沙盒档位

| 沙盒档位 | 直觉理解 | 适合场景 |
| --- | --- | --- |
| `read-only` / 只读 | 能看，不能直接改 | 问答、代码审查、解释项目、风险分析 |
| `workspace-write` / 工作区写入 | 能在当前工作区内改文件和运行常规命令 | 日常开发、修 bug、跑测试 |
| `danger-full-access` / 完全访问 | 基本取消普通沙盒边界 | 明确需要本机广泛访问，且你信任当前任务 |

风险排序大致是：

`read-only` < `workspace-write` < `danger-full-access`

## 三、批准策略和沙盒设置的关系

可以把它们看成两个维度：

| 维度 | 负责的问题 |
| --- | --- |
| 沙盒设置 | Codex 技术上能不能做某件事 |
| 批准策略 | Codex 遇到越界或高风险动作时，谁来决定是否放行 |

也就是说：

- 沙盒设置定义边界。
- 批准策略定义遇到边界时的处理方式。

## 四、对话框三个权限选项

| 对话框选项 | 大致含义 | 和沙盒的关系 |
| --- | --- | --- |
| 请求批准 | Codex 在沙盒内自动工作，越界时问用户 | `approval_policy = on-request`，审查人是用户 |
| 替我批准 | Codex 仍在沙盒内工作，越界时交给自动审查 agent 判断 | 沙盒边界不变，只是批准者从用户换成自动审查 |
| 完全访问 | Codex 不再受普通沙盒限制，也不再弹批准请求 | 通常等价于 `sandbox_mode = danger-full-access` + `approval_policy = never` |

关键区别：

> 「替我批准」不是「完全访问」。它不扩大沙盒边界，只是改变越界时由谁批准。

## 五、默认沙盒和当前对话权限谁优先

本次讨论里的配置是：

- 配置页默认沙盒：只读
- 对话框当前选择：完全访问

实际影响是：

> 当前这个对话会按「完全访问」运行，而不是按配置页里的默认只读沙盒运行。

可以理解为：

1. 配置页里的沙盒设置是默认值。
2. 对话框里的权限选择是当前会话的覆盖值。
3. 如果当前对话选择「完全访问」，本次会话就绕过默认只读边界。

这不代表配置页沙盒无意义。它仍然是：

- 新会话默认边界
- 使用「请求批准」或「替我批准」时的越界判断基础
- 没有手动选择更高权限时的安全基线

## 六、如果默认只读但本次选了完全访问

实际效果：

- Codex 可以读取、写入工作区文件。
- Codex 可能访问工作区外路径。
- 执行命令时不会因为普通沙盒权限再向用户请求批准。
- 风险显著高于只读或工作区写入。

但仍然会受到其他规则约束，例如本库的 `AGENTS.md` 要求：

> 需要删除文件时，要请求用户。

所以即使当前会话是完全访问，也不代表可以无视用户指令或项目规则。

## 七、什么时候选什么

| 场景 | 建议 |
| --- | --- |
| 只想问概念、解释代码、审查风险 | 只读 + 请求批准 |
| 想让 Codex 修改当前项目、跑测试 | 工作区写入 + 请求批准 |
| 频繁要改文件，但希望减少手动确认 | 工作区写入 + 替我批准 |
| 明确要让 Codex 广泛操作本机，并且任务可信 | 完全访问 |

更保守的默认做法：

> 平时用 `workspace-write`，需要越界时再单次批准；不要长期把普通对话都开成完全访问。

## 八、一个最小心智模型

```text
配置页沙盒设置
  = 默认安全边界

对话框权限选择
  = 本次会话如何运行

请求批准 / 替我批准
  = 仍依赖沙盒边界，只是批准者不同

完全访问
  = 本次会话显式覆盖默认沙盒，风险最高
```
