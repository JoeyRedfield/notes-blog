# AI 编码能力提升路线

> 基于当前技术背景（Java 后端 + AI 应用开发 + Claude Code 深度使用）和近期摄入的 Matt Pocock、Josh Kaufman、Jensen Huang 演讲，梳理的 AI 编码能力提升方向。

## 一、把"Grill Me"变成肌肉记忆

**来源**：[[软件基础在AI时代更重要——Matt Pocock|Matt Pocock 演讲]] 失败模式一

AI 没做你想要的，根源是设计概念没对齐。目前用 Claude Code 时，很可能直接描述需求就让它开始写代码。

**做法**：每次开始稍复杂的任务，先加一句引导——"先问我 10-15 个问题，确认你对需求的理解和我一致，再开始动手"。不需要额外工具，只是一句 prompt 习惯的改变。用几周变成默认习惯后，AI 产出代码质量会明显提升。

## 二、开始用 TDD 控制 AI 的输出节奏

**来源**：[[软件基础在AI时代更重要——Matt Pocock|Matt Pocock 演讲]] 失败模式三

之前项目（苍穹外卖、天机学堂）没系统用过 TDD。关键论点不是"TDD 是好的工程实践"，而是**"TDD 是控制 AI 输出质量的关键机制"**。

AI 的默认行为是一次产出一大坨代码然后才想检查。TDD 强制它小步走：先写测试 → 让测试过 → 重构。

**做法**：拿到一个新的业务任务时，不要急着让 AI 写业务代码。先让它帮你写测试用例，你再审查测试是否合理，然后让它实现。比"直接写代码再调试"效率高很多。

## 三、建立每个项目的"通用语言"文件

**来源**：[[软件基础在AI时代更重要——Matt Pocock|Matt Pocock 演讲]] 失败模式二 + DDD Ubiquitous Language

纯靠 Claude Code 做事时，术语理解靠每次对话的上下文窗口——但上下文窗口里没有术语说明。

**做法**：进入一个术语密集的业务系统代码库时，第一件事不是写代码，而是让 AI 扫描代码库提取术语表（如入库单、波次、库位、拣货策略等）。以后每次对话都引用这个文件。一劳永逸，持续提升 AI 对业务代码的理解精度。

## 四、把 Spring Boot 分层架构当成"深度模块"来维护

**来源**：[[软件基础在AI时代更重要——Matt Pocock|Matt Pocock 演讲]] 失败模式四、五 + John Ousterhout 深度模块理论

已有的 Spring Boot 项目经验（Controller → Service → Mapper）天然是深度模块结构。

- **Controller 接口 = 你控制**（REST API 设计、参数校验）
- **Service 实现 = 可以大胆交给 AI**（前提是接口和测试你已把关）
- **不要让 AI 动了你的分层边界**

关键意识转变：不是"AI 帮我写了这段 Service"，而是"**我定义了 Service 的接口和契约，AI 填充了实现**"。

## 五、Python 学习用 20 小时框架起步

**来源**：[[前20小时学会任何技能|Josh Kaufman 20 小时法则]]

画像里写着"要系统学 Python，目标脱离 AI 独立开发"。20 小时框架比"找一本 Python 书从头啃"更务实：

| 步骤 | Python 应用 |
|------|------------|
| 拆解 | Python 语法基础 → 常用标准库（os, json, requests, pathlib）→ FastAPI 基础。先练前两块 |
| 学到能自纠 | 一本教程快速过 + 官方文档速览。**不要收集 10 本 Python 书再开始** |
| 移除障碍 | 每天固定 45 分钟，VS Code 开专门练习目录 |
| 预承诺 20 小时 | 撑过"语法都写不顺"的初始挫败阶段 |

## 六、核心信念：你是战略层，AI 是战术层

**来源**：[[软件基础在AI时代更重要——Matt Pocock|Matt Pocock 演讲]] + [[黄仁勋震撼演讲|黄仁勋演讲]]

黄仁勋说"每天检验你的核心信念"→ 核心信念可以是：**"我负责设计系统、审查代码、做架构决策。AI 负责填充实现。"**

不要因为 AI 写代码比你快就动摇——你真正的价值是你知道**什么该做、怎么做、为什么这样做**。这也是 Matt 说的"Invest in the design of the system every day"。

## 总结

从"让 AI 帮我写代码"升级到"**我设计 + AI 执行 + 我审查**"——这个三角循环里的两个角（设计、审查）靠的是软件基础，不是 AI 技巧。
