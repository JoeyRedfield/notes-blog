# 三角循环——AI 编码核心概念内化记录

> 2026-06-03 交互式 Review 学习记录。将近期摄入的 5 篇高优先级笔记（Matt Pocock 两场演讲、Agentic Engineering 技巧集、AI 原生工程团队、Harness Engineering）统一为可执行的心智模型。

## 核心模型

> **Grill Me 对齐 → 我设计接口 → AI 用 TDD 在深度模块内填充实现 → 我审查测试和契约**

拆解开：

- **我设计**：接口契约、分层边界、术语定义——靠软件基础
- **AI 执行**：在深度模块内部，用 TDD 红绿重构循环自主编码
- **我审查**：先看测试是否合理，再看实现代码——清空上下文再审

## 五个知识点

### 1. 坏代码比以往任何时候都更贵

不只是"AI 一次产出大量坏代码修复成本高"（量变）。质变在于：

> 坏代码库让 AI **失去了自我纠错的能力**。

AI 纠错的前提是能快速看到自己代码的运行结果（编译 → 测试 → lint）。如果反馈循环断了，AI 在盲写，产出的代码需要你自己手动调试——你就拿不到 AI 的全部红利。

**关键公式**：反馈循环的质量 = AI 编码质量的天花板

**好代码库**：AI 写 → `mvn test` 3 秒 → 看到红线 → 自己改 → 绿了。整个循环 30 秒，不需要你。

**烂代码库**：AI 写 → 测试跑不起来（耦合太重、mock 不了）→ AI 看不到反馈 → 继续在错误方向上堆代码。

### 2. Grill Me——在动手前让 AI 拷问你

`grill-me` skill 的用法不是"你已经想清楚了再让 AI 确认"——恰恰相反，是**当需求还很模糊时用**。

AI 变成对手方，持续追问（可能 40-100 个问题），直到达成共享设计概念。整个对话过程可以直接转化为 PRD 或 Issues。

**关键认知**：这不是需求确认，这是**把模糊想法变成清晰设计**的过程。比 Claude Code 默认的 Plan Mode 更好，因为 Plan Mode 急于产出文档，Grill Me 先建立共享理解。

### 3. TDD 在 AI 时代的新角色——不是质量保障，是反馈循环

"先测试后实现"和"先实现后调试"的区别不只是**顺序**，而是**谁在看结果**。

- **传统调试**：你写代码 → 部署 → 手工测试 → 你用眼睛看 → 发现 bug → 告诉 AI 改。**瓶颈是你的注意力**。
- **AI TDD**：AI 写测试 → 看到红灯 → 写实现 → 看到绿灯 → 重构。**你不在循环里**。

你的工作不是让 AI 先写测试，而是**搭建一个 AI 能自己看、自己改、自己验证的闭环**。Java 项目里 JUnit + `mvn test` 就是 AI 的眼睛。

### 4. 深度模块——你设计接口，AI 填充实现

Spring Boot 的 Controller → Service → Mapper 天然是深度模块结构。

直接让 AI 写 `reduceStock(skuId, qty)` 可能和深度模块做法的结果代码一模一样。但区别在于**一个月后**：

- **你设计了接口**：你知道契约是什么，新需求来的时候知道在哪改，不需要重读 200 行代码
- **你没设计接口**：你必须从头读一遍 AI 的代码才能安全改动

这就是"灰盒思维"——你只记接口契约（壳），不记实现细节（核）。认知负荷从"理解一切"降到"理解边界"。

### 5. 五大失败模式

| # | 失败模式 | 解药 |
|---|---------|------|
| 1 | AI 没做我想要的东西 | **Grill Me**（共享设计概念） |
| 2 | AI 太啰嗦，词汇不对齐 | **通用语言**（Ubiquitous Language） |
| 3 | AI 写的东西不能运行 | **TDD + 反馈循环** |
| 4 | 测试本身就很难写 | **深度模块**（简单接口 + 大量内部封装） |
| 5 | 大脑跟不上了 | **设计接口，委派实现**（灰盒思维） |

## 自我检验结果

- **知识点 1（坏代码更贵）**：初答在量变层面（"一次产出大量坏代码"），经过追问意识到质变层面（"AI 失去自我纠错能力"）
- **知识点 2（Grill Me）**：初答将其理解为"对项目有清晰认知时才适用"，纠正为"当需求模糊时用，AI 帮你问清楚"
- **知识点 3（TDD）**：概念薄弱（此前无 TDD 经验），理解了"你不在反馈循环里"的关键区别
- **知识点 4（深度模块）**：初答聚焦"出错时返工"，补充了"成功时维护认知负荷"的视角
- **知识点 5（五大模式）**：无法复述——验证了"摄入多、吸收少"的自我怀疑

## 应用场景

### 进入业务系统项目后的理想流程

```
收到"入库单查询接口"需求
  ↓
Phase 1: Grill Me（追问：谁查？什么条件？分页？实时/缓存？权限？）
  ↓
Phase 2: 建立通用语言文件（入库单、库位、SKU、波次……）
  ↓
Phase 3: 设计接口契约（输入/输出/异常/幂等性）
  ↓
Phase 4: AI 用 TDD 在 Service 层内填充实现
  ↓
Phase 5: 清空上下文后人工审查（先看测试，再看实现）
```
