# 政策信号到行动清单：学什么、做什么项目

> [!note]
> 本页是 [[AI时代软件开发职业方向]] 的**执行页**。
> 它不再重复论证“方向为什么成立”，而是直接回答：接下来该学什么、先做什么项目、怎么按 6 周节奏推进。

## 一句话结论

如果把最近这组政策信号翻译成行动，不是“再多看点 AI 资讯”，而是尽快补齐一套**能把 agent 接入真实业务系统并做出可演示项目**的能力组合。

## 先判断主线

你的主线不建议写成“我想转 AI”，而应该写成：

> **我做 AI Agent 应用开发，同时保留 AI 赋能后端的工程化能力。**

这样有两个好处：

- 能和政策里的客服、运营、决策、零售、电商、物流等场景对上
- 也能继续吃到你已有后端基础的复利，而不是从零换赛道

## 该学什么

### 第一层：先补到能做项目

这部分的目标不是学深，而是尽快到“能独立做 demo + 能解释设计”的程度。

- Python：语法、函数、类、HTTP 请求、基本异步
- LLM 调用基础：模型 API、流式输出、函数调用、结构化输出
- RAG 基础：文档切分、向量化、检索、重排、生成
- Tool/Agent 基础：工具调用、状态管理、简单工作流编排
- 后端集成基础：把 agent 接到数据库、业务 API、文件系统、消息通知

### 第二层：补工程化能力

这部分会直接拉开“会玩 demo”和“能做业务系统”的差距。

- Prompt 版本管理
- 日志、评测、监控
- 权限控制与审计
- 成本控制与模型路由
- 回滚机制与人工兜底
- 失败重试与异常处理

### 第三层：补行业理解

政策已经把场景点得很清楚，所以至少要挑一个行业链路吃透：

- 电商零售
- 物流配送
- 客服工单
- 养老服务

重点不是行业百科，而是搞清楚：

- 这个场景里谁在用系统
- 他们现在怎么做
- 哪一步最费人
- 哪一步最适合 agent 介入

## 该做什么项目

### 项目 1：智能客服 / 工单助手

目标：证明你能把 LLM 接进一个流程型系统，而不是只会聊天。

建议能力点：

- FAQ/RAG 检索
- 工单分类与优先级判断
- 调用内部工具查询订单或状态
- 输出结构化处理建议
- 人工确认后再执行

这个项目最适合当第一个代表作，因为场景清晰、演示容易、和政策里的客服/运营方向高度一致。

### 项目 2：零售/电商运营助手

目标：证明你能做“业务数据 + agent + 输出结果”的闭环。

建议能力点：

- 查询商品、订单、销售数据
- 自动生成日报/周报
- 异常波动解释
- 活动建议或补货建议
- 导出 Excel/Markdown 报告

这个方向和你已有后端能力结合很好，也更容易往“智能运营”上靠。

### 项目 3：物流/调度助手

目标：证明你不只会文本处理，还能处理规则、约束和流程。

建议能力点：

- 查询配送状态
- 异常订单识别
- 按规则给出调度建议
- 多条件筛选与结构化输出
- 失败兜底和人工审批

这个项目更难，但一旦做出来，含金量会高于普通 RAG 项目。

## 先后顺序

建议按这个顺序推进：

1. **先做客服/工单助手**
2. **再做电商/零售运营助手**
3. **最后做物流/调度助手**

原因：

- 第一个项目解决“能不能做出来”
- 第二个项目解决“能不能和业务数据结合”
- 第三个项目解决“能不能处理复杂流程和约束”

## 接下来 6 周怎么推

### 第 1-2 周

- 补 Python 到可写 agent/tool 的程度
- 跑通一次模型调用、工具调用、RAG 检索
- 做出客服/工单助手最小可运行版

### 第 3-4 周

- 给项目补日志、结构化输出、失败兜底
- 做一个零售/电商运营助手
- 开始整理项目说明文档和演示脚本

### 第 5-6 周

- 做物流/调度类原型
- 补评测、监控、成本控制意识
- 把三个项目整理成可讲述的作品集

## 做项目时要刻意展示的能力

- 不只是“能回答”，而是“能调用工具完成一步业务动作”
- 不只是“能做 demo”，而是“知道失败时怎么兜底”
- 不只是“会调 prompt”，而是“会设计流程、权限、日志和回滚”
- 不只是“懂 AI”，而是“能和真实业务系统集成”

## 不建议现在优先做的事

- 深入卷模型训练和微调
- 花很长时间学纯理论课程
- 做和业务场景无关的炫技型 AI 项目
- 为了“像 AI 工程师”而放弃你已有的后端优势
