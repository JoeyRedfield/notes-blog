# 先建立一个调试框架

以后你遇到问题，先按这 4 层排查：

## 第 1 层：配置层

看这些：

- `.env` 有没有写对
    
- API Key 有没有配
    
- `BASE_URL` 对不对
    
- `MODEL_NAME` 对不对
    

典型现象：

- 一启动就失败
    
- 报“缺少 API Key”
    
- 报 401、403、model not found
    

---

## 第 2 层：请求层

看这些：

- 网络是否正常
    
- 请求是否发出去了
    
- 参数格式是否正确
    

典型现象：

- 超时
    
- 连接失败
    
- 请求参数错误
    

---

## 第 3 层：模型输出层

看这些：

- 模型有没有按要求回答
    
- 有没有输出多余解释
    
- JSON 是否真的合法
    

典型现象：

- 本来要 JSON，结果返回了一大段解释
    
- 漏字段
    
- priority 输出成“紧急”
    

---

## 第 4 层：程序处理层

看这些：

- `json.loads()` 是否成功
    
- `.strip()` 会不会报错
    
- 字段缺失后有没有兜底
    

典型现象：

- `JSONDecodeError`
    
- `AttributeError`
    
- `KeyError`
    
- 类型错误
    

---

# Day 5 你要记住的一句话

> **调试不是乱猜，而是缩小问题范围。**

比如 `extract_json.py` 出错时，不要一上来就说“模型不行”。

先问：

1. 模型原始输出是什么？
    
2. 是不是合法 JSON？
    
3. Python 是在哪一行报错？
    
4. 是字段值不合法，还是格式不合法？

## 任务 1：给 `chat_cli.py` 增加更清楚的初始化提示

你现在可以把初始化部分改得更清楚一点。

### 建议目标

启动时打印：

- 是否成功读取配置
    
- 当前 `base_url`
    
- 当前 `model_name`
    

这样以后切模型或切服务商时更容易查问题。

### 建议写法

```python
print("正在加载配置...")
api_key, base_url, model_name = load_config()
print("配置加载成功。")
print(f"BASE_URL: {base_url}")
print(f"MODEL_NAME: {model_name}")
```

注意：

- 不要打印完整 API Key
    
- 最多只打印“已读取 API Key”
    

比如：

```python
print("API Key 已读取。")
```

# 你今天要做的 3 个“故意出错”实验

---

## 实验 1：故意把 `.env` 里的 API Key 改错

比如把：

```env
DASHSCOPE_API_KEY=xxxx
```

改成空，或者乱写一个值。

### 你要观察

- 程序是在启动时报错，还是请求时报错？
    
- 报错信息像不像你能看懂的“配置问题”？
    

### 你要得到的认识

这类错误属于：  
**配置层 / 鉴权层问题**

---

## 实验 2：故意把 `MODEL_NAME` 改成一个不存在的名字

比如：

```env
MODEL_NAME=abc-test-model
```

### 你要观察

- 程序能不能启动
    
- 真正发请求时怎么报错
    

### 你要得到的认识

这类错误属于：  
**请求参数 / 模型配置问题**

---

## 实验 3：故意让 `extract_json.py` 返回不规范值

你可以临时把 Prompt 改弱一点，比如删掉：

- “只能输出 JSON”
    
- “priority 只能是 高 / 中 / 低”
    

然后输入一条模糊文本：

```text
这个事情尽快弄一下，最好今天搞定
```

### 你要观察

- 模型原始返回有没有可能不规范
    
- `validate_result()` 能兜住多少
    
- 哪些问题是 prompt 能解决的
    
- 哪些问题必须程序兜底
    

### 你要得到的认识

这类错误属于：  
**模型输出层 + 程序校验层问题**

# 今天建议你顺手做的两个代码改进

---

## 改进 1：给 `extract_json.py` 单独封装一个打印函数

这样日志更清楚。

例如：

```python
def debug_log(title, content):
    print(f"\n[DEBUG] {title}")
    print(content)
```

然后这样用：

```python
debug_log("用户输入", text)
debug_log("模型原始返回", content)
```

这不是必须，但很适合你现在练习“调试思维”。

---

## 改进 2：给 `chat_cli.py` 把异常提示写得更具体一点

比如现在是：

```python
print(f"请求失败：{e}\n")
```

你可以改成：

```python
print("请求失败，请检查以下几项：")
print("1. API Key 是否正确")
print("2. BASE_URL 是否正确")
print("3. MODEL_NAME 是否存在")
print(f"具体错误信息：{e}\n")
```

这样以后你看到错误时，不会只剩下一句“失败了”。

# 今天你需要特别区分的两个概念

## 1. “模型回答不理想” 不等于 “代码报错”

例如：

- priority 判错了
    
- task_name 太模糊了
    

这说明：

- 代码没坏
    
- 但业务效果不好
    

这时你要改的是：

- Prompt
    
- 校验规则
    
- 输入设计
    

而不是怀疑 Python 代码崩了。

---

## 2. “代码报错” 不等于 “模型太笨”

例如：

- `json.loads()` 报错
    
- `.strip()` 报错
    
- `NoneType` 报错
    

这往往是：

- 你程序没有处理边界情况
    
- 不是模型本身的问题
