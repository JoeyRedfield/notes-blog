下面这套计划是按你的当前状态设计的：**Python 能看懂和改代码，但还不适合一上来就堆太多框架**。所以路线会是：

**先学原生能力（Prompt / API / Tools / RAG / Evals）→ 再做项目 → 最后再引入 LangChain / LangGraph。**

这样更容易真正形成“自己能从 0 做出可运行 AI 应用”的能力。

从官方文档看，这个顺序也合理：通义千问官方提供了原生 API 与 OpenAI 兼容接口，并支持 Function Calling；智谱官方也提供对话补全、工具调用和结构化输出能力，所以前期完全可以先用**原生 Python + 模型 API**把核心能力学扎实。LangChain 更适合做模型、检索、工具等组件整合；LangGraph 更适合做**长流程、带状态、可恢复**的 agent/workflow，这些都更适合放到后半程再介入。向量检索层面，Chroma 文档强调 collection 中可存 embeddings、documents、metadata 并做检索，FAISS 本身则是做 dense vector similarity search 的高效库；Evals 方面，LangSmith 官方文档强调它可以围绕 dataset 和 experiment 做评测与回归。([阿里云帮助中心](https://help.aliyun.com/zh/model-studio/qwen-function-calling?utm_source=chatgpt.com "如何通过Function Calling 实现工具调用 - 阿里云文档"))

# 总路线图

## 阶段 1：先把“调用模型”这件事做对（第 1–2 周）

你先学会 4 个基本功：

1. **Prompt**
    
2. **Python 调用 LLM API**
    
3. **结构化输出**
    
4. **Tools / function calling 基础**
    

这一阶段的目标不是“做复杂 Agent”，而是做到：

- 你能独立写一个 Python 脚本调用模型
    
- 你能控制输入输出格式
    
- 你能让模型决定是否调用工具
    
- 你知道哪里是 prompt 问题，哪里是代码问题，哪里是模型能力边界
    

---

## 阶段 2：把“知识接入”做起来（第 3–4 周）

核心是：

1. **Embedding 是什么**
    
2. **RAG 的最小闭环**
    
3. **向量数据库 / 向量索引基础**
    
4. **Evals 初步**
    

这一阶段结束时，你要能做出第一个完整项目：

**项目 A：本地文档问答助手**

---

## 阶段 3：从“单轮调用”升级到“可行动系统”（第 5–6 周）

核心是：

1. **Agent 基础**
    
2. **Memory 的正确理解**
    
3. **多工具协同**
    
4. **应用状态管理**
    

这一阶段结束时，你会开始做第二个项目：

**项目 B：带工具与记忆层的个人求职/学习助手**

---

## 阶段 4：最后再引入框架抽象（第 7–8 周）

你会学习：

1. **LangChain 什么时候值得用**
    
2. **LangGraph 什么时候必须用**
    
3. **Evals 回归测试**
    
4. **把项目整理成可展示作品**
    

这一阶段的目标不是“学会所有框架 API”，而是知道：

- 不用框架时怎么做
    
- 用 LangChain 能省什么
    
- 用 LangGraph 是为了解决什么复杂度

## 第 1 周：Prompt + Python 调用 LLM API

### 学习主题

- Prompt 基础
    
- `requests` / 官方 SDK / OpenAI-compatible SDK 调模型
    
- 环境变量、错误处理、日志打印
    
- 结构化输出入门
    

### 学习目标

- 能用 Python 成功调用一次模型
    
- 能区分 `system prompt`、`user prompt`、输出格式约束
    
- 能让模型稳定输出 JSON
    
- 知道“提示词调优”不是玄学，而是**输入约束 + 输出约束 + few-shot 示例**
    

### 必学

- prompt 的角色分层：system / user / examples
    
- Python 基本 I/O、函数、异常处理
    
- `.env`、API Key 管理
    
- 让模型返回 JSON
    
- 基本参数：`temperature`、`max_tokens`
    

### 可后学

- streaming 输出
    
- async 调用
    
- 多模态输入
    

### 暂时不用学

- fine-tuning
    
- multi-agent
    
- LangGraph
    
- MCP
    

### 实操作业

- 写一个 `chat_cli.py`
    
- 支持从命令行输入问题，输出模型回复
    
- 再写一个 `extract_json.py`，把一段文本抽取成结构化 JSON，比如：
    
    - 任务名称
        
    - 截止日期
        
    - 优先级
        

### 一个最小可运行项目

**Prompt 实验台 v0**

- 输入：一段需求文本
    
- 输出：规范化 JSON
    
- 技术栈：Python + 通义千问或智谱 API
    
- 目标：把“自然语言 → 结构化输出”跑通
    

### 这一周你真正要建立的认知

- **Prompt 是接口设计，不是文学创作**
    
- 先把输出稳定下来，再谈“更聪明”

## 第 2 周：Tools / Function Calling 基础

### 学习主题

- function calling / tool calling
    
- 工具 schema 设计
    
- 模型决定何时调用工具
    
- Python 侧执行工具并回填结果
    

### 学习目标

- 理解“模型不是直接执行代码，而是生成工具调用意图”
    
- 能写 2–3 个本地工具并接到模型上
    
- 能完成一轮“模型选工具 → Python 执行 → 模型组织最终回答”的闭环
    

通义千问官方文档明确给出了 Function Calling 流程：传入 `tools` 与 `messages` 后，模型会决定是否调用工具，并返回函数名与参数。智谱官方文档也将工具调用作为标准能力提供。([阿里云帮助中心](https://help.aliyun.com/zh/model-studio/qwen-function-calling?utm_source=chatgpt.com "如何通过Function Calling 实现工具调用 - 阿里云文档"))

### 必学

- function schema / JSON schema 基本写法
    
- 本地工具封装：如 `calculator()`、`get_time()`、`read_note()`
    
- 参数校验
    
- 工具调用结果回填
    

### 可后学

- 调用外部 HTTP API 的工具
    
- 并行工具调用
    
- 工具权限控制细化
    

### 暂时不用学

- ReAct 复杂提示
    
- LangChain Agent
    
- LangGraph state machine
    

### 实操作业

写一个小助手，支持这些工具：

- `get_current_time`
    
- `calculate_expression`
    
- `read_local_note`
    

要求：

- 模型自己决定是否调用工具
    
- 如果不用工具，直接回答
    
- 如果用工具，输出清晰的中间日志
    

### 一个最小可运行项目

**本地工具助手 v0**

- 用户问：“现在几点了”“帮我算 23*17”“帮我读一下这份笔记”
    
- 助手自动调用对应工具并返回答案
    

### 这一周你真正要建立的认知

- **Tools 是把 LLM 从“会说”变成“能做事”**
    
- 但 Agent 的核心不是“会调很多工具”，而是**流程可控**

## 第 3 周：RAG 与向量数据库基础

### 学习主题

- Embedding 基础
    
- chunking
    
- top-k retrieval
    
- 向量数据库 / 向量索引基础
    
- RAG 最小链路
    

Chroma 官方文档把 collection 定义为存储 embeddings、documents、metadata 并支持检索的基础单元；FAISS 官方说明它是用于 dense vectors 的高效 similarity search 与 clustering 库。([docs.trychroma.com](https://docs.trychroma.com/docs/overview/getting-started?utm_source=chatgpt.com "Getting Started - Chroma Docs"))

### 学习目标

- 理解 RAG 的基本流程：  
    **文档切块 → 向量化 → 检索 → 拼接上下文 → 生成答案**
    
- 明白向量数据库不是“记忆系统”，本质是**检索层**
    
- 能自己做一个本地文档问答 demo
    

### 必学

- embedding 的作用
    
- 文本切块：chunk size / overlap
    
- metadata 的基本用途
    
- top-k 检索
    
- prompt 中如何注入检索结果
    

### 可后学

- reranker
    
- hybrid search
    
- query rewriting
    

### 暂时不用学

- Graph RAG
    
- Agentic RAG
    
- 复杂召回融合
    

### 实操作业

选你自己的材料做知识库，例如：

- AI 应用开发学习笔记
    
- Python 学习笔记
    
- 求职资料 / 简历 / 岗位 JD
    

要求：

- 能导入 txt / md
    
- 能检索最相关片段
    
- 能基于检索结果回答问题
    
- 答案里带出处片段或 chunk id
    

### 一个最小可运行项目

**本地笔记问答 v0**

- 输入：问题
    
- 输出：答案 + 命中的原文片段
    

### 这一周你真正要建立的认知

- **RAG 不是让模型“知道更多”，而是让系统“拿到相关上下文”**
    
- 向量数据库解决的是“找”，不是“懂”

## 第 4 周：RAG 调试 + Evals 入门，完成项目 A

### 学习主题

- RAG 失败分析
    
- Evals 基础
    
- 建立小型测试集
    
- 项目 A 收尾
    

LangChain 文档中明确区分了普通 2-step RAG 与 agentic RAG；LangSmith 文档则强调 evals 需要基于 dataset / experiment 去测质量，而不是只靠主观感觉。([LangChain 文档](https://docs.langchain.com/oss/python/langchain/retrieval?utm_source=chatgpt.com "Retrieval - Docs by LangChain"))

    - chunk 切坏了

- 做出第一个像样的小项目
    

### 必学

- 手工构造 20 条测试问题
    
- 记录：
    
    - 是否检索到正确 chunk
        
    - 最终答案是否正确
        
    - 幻觉率大不大
        
- prompt 版本对比
    
- 简单回归测试思路
    

### 可后学

- LangSmith UI
    
- 自动打分 evaluator
    
- 在线监控
    

### 暂时不用学

- 生产级 tracing 平台
    

### 实操作业

给你的知识库做一个 `evals.jsonl`：

- 每条包含 `question`
    
- `expected_answer` 或 `expected_chunk_keywords`
    
- 跑 20 条问题
    
- 记录命中率和主观评分
    

### 一个最小可运行项目

## 项目 A：文档问答助手 v1

建议做成：

- CLI 版，或者
    
- `Streamlit` 简单网页版
    

最少要有：

- 文档导入
    
- 向量检索
    
- 回答生成
    
- 来源展示
    
- 10–20 条测试样例
    

### 这一周你真正要建立的认知

- **没做 eval 的 AI 应用，基本等于“感觉能用”**
    
- 你从这周开始，要建立“先测再改 prompt”的习惯

## 第 5 周：Agent 基础 + Memory 的正确理解

### 学习主题

- agent 的最小定义
    
- 工具循环
    
- Memory 分层
    
- 状态持久化
    

### 学习目标

- 理解什么是 agent，什么不是
    
- 理解 memory 不等于“模型脑子里记住你”
    
- 能做一个带最小记忆层的助手
    

### 必学

- Agent 最小结构：
    
    - 用户目标
        
    - 工具集
        
    - 状态
        
    - 停止条件
        
- Memory 的正确理解：
    
    1. **Context memory**：当前轮上下文
        
    2. **Session memory**：当前会话历史
        
    3. **Profile memory**：用户偏好/长期资料
        
    4. **Retrieval memory**：把历史内容检索回来再喂给模型
        
- 用 JSON / SQLite 存状态
    

### 可后学

- episodic memory / semantic memory 这些术语扩展
    
- reflection / self-critique
    
- long-term memory ranking
    

### 暂时不用学

- 多智能体协作
    
- 自动长期规划
    
- 自主浏览网页 agent
    

### 实操作业

做一个助手，支持：

- 记住“你的学习目标”
    
- 记住“你最近在做什么项目”
    
- 下次对话能读回来
    
- 结合这些信息生成更个性化建议
    

### 一个最小可运行项目

**学习助手 v0（带记忆层）**

- 工具：
    
    - `save_profile`
        
    - `load_profile`
        
    - `save_task`
        
    - `list_tasks`
        
- 状态存到本地 JSON 或 SQLite
    

### 这一周你真正要建立的认知

- **Memory 是应用层设计，不是模型神秘能力**
    
- 很多所谓“记忆”其实只是：
    
    - 保存
        
    - 检索
        
    - 再注入上下文

## 第 7 周：LangChain / LangGraph 的介入时机

### 学习主题

- LangChain 的定位
    
- LangGraph 的定位
    
- 什么时候值得引入框架
    
- 把旧项目做一次框架化重构
    

官方文档里，LangChain 被定义为带有预构建 agent 架构以及模型、工具等集成能力的框架；LangGraph 则被定义为面向**long-running、stateful workflow or agent** 的低层支撑设施。([LangChain 文档](https://docs.langchain.com/oss/python/langchain/overview?utm_source=chatgpt.com "LangChain overview - Docs by LangChain"))

### 学习目标

- 知道什么时候**不该**上框架
    
- 知道什么时候 LangChain 可以帮你少写很多胶水代码
    
- 知道什么时候 LangGraph 才值得上
    

### 必学

- LangChain：
    
    - prompt template
        
    - model wrapper
        
    - retriever
        
    - tool 封装
        
- LangGraph：
    
    - state
        
    - node
        
    - edge
        
    - 条件跳转
        
    - checkpoint 思想
        

### 可后学

- LangSmith tracing
    
- prebuilt agents
    
- human-in-the-loop
    

### 暂时不用学

- 复杂 multi-agent graph
    
- 生产级 orchestration
    

### 实操作业

二选一：

1. 用 LangChain 重写项目 A 的检索部分
    
2. 用 LangGraph 写一个 3 节点工作流：
    
    - 解析需求
        
    - 调工具
        
    - 生成结果
        

### 一个最小可运行项目

**LangGraph 工作流 demo**

- 输入用户任务
    
- 根据任务决定是否走工具节点
    
- 最终输出结果和流程日志
    

### 这一周你真正要建立的认知

**LangChain 的介入时机：**

- 你已经会原生调用了
    
- 你不想重复写 prompt / retriever / tool glue code
    
- 你需要更快拼装组件
    

**LangGraph 的介入时机：**

- 你的流程有多步状态
    
- 有条件分支
    
- 需要 checkpoint / 恢复 / 人工介入
    
- 普通 while-loop 已经开始乱了

# 结合 ChatGPT 的正确学习方式

你已经有 ChatGPT Plus，这对学习非常有帮助，但建议你把它当成这 4 种角色来用：

## 1. 概念教练

让它帮你：

- 解释 embedding、RAG、tool calling
    
- 对比“直接调用 API”和“用 LangChain”的差别
    
- 给你出小练习
    

## 2. 代码助教

让它帮你：

- 解释报错
    
- 改完整代码
    
- 给最小可运行示例
    
- 做 code review
    

## 3. 测试设计师

让它帮你：

- 生成 evals 数据集
    
- 设计失败样例
    
- 写 prompt A/B 测试输入
    

## 4. 项目复盘助手

让它帮你：

- 分析项目哪里过度设计
    
- 帮你整理 README
    
- 模拟面试官问你项目细节
    

但有一条很重要：

**ChatGPT 用来帮你“理解、拆解、纠错”，不是替你跳过实践。**  
每周至少有一个脚本必须是你自己从头敲出来的。
