此外，③是递归的base case, 即退出条件. 

写的时候注意base case要在递归函数的前面, 不然运行会报错. 

```c++
#include <iostream>
using namespace std;

// 1.
//void printX(){
//    cout << "print x base case" << endl;
//}

// 2.
template <typename... Types>
void printX(const Types&... args) {
    std::cout << "printX 1" << std::endl;
    // This version doesn't print any arguments, just a message.
    // It's the base case for the recursion.
}

// 3.
template <typename T, typename... Types>
void printX(const T& firstArg, const Types&... args) {
    std::cout << "printX 2" << std::endl;
    std::cout << firstArg << std::endl;
    printX(args...);
}

int main() {
    int a = 42;
    double b = 3.14;
    std::string c = "Hello";
    char d = '!';
    printX(a, b, c, d);
    return 0;
}
printX 2
42
printX 2
3.14
printX 2
Hello
printX 2
!
printX 1
```

上面的测试可以得出结论, 1+n更特化, 而n可以作为base case, 更泛化. 此外, 如果有`1.`的话, 递归终止后不会执行`2.`而会去执行`3.`

# nullptr and std::nullptr_t

nullptr算是给指针用的, 因为以前设空指针一般用0或NULL, 不太对味. 而且因为NULL实际上定义也是0, 在某些情况下会有问题, 如下: 

![[Untitled 786.png]]

std::nullptr_t定义在<cstddef>头文件

> `std::nullptr_t`和`nullptr`是C++11引入的两个关于空指针的概念，它们之间有一些区别。
> 1. `std::nullptr_t`：
> `std::nullptr_t`是一个**特殊的类型，用于表示空指针常量**。它实际上是一个空类型，用于标识不指向任何对象或函数的指针。在C++11之前，为了确定空指针，通常使用`0`或`NULL`（通常被定义为`(void*)0`）。但**这样的做法可能在重载函数的情况下引发歧义**，因为`0`或`NULL`可能与其他整数类型匹配。使用`std::nullptr_t`可以明确地表示空指针，避免了这种歧义。
> 2. `nullptr`：
> `nullptr`是C++11引入的**关键字**，用于表示空指针常量。它实际上就是一个`std::nullptr_t`类型的字面量值，用于代替传统的`NULL`或`0`。使用`nullptr`也可以明确地表示空指针，而且更安全，因为它不会被错误地解释为整数类型。
> 
> 总结：
> 
> - `std::nullptr_t`是一个特殊类型，用于表示空指针的类型。
> - `nullptr`是一个关键字，用于表示空指针常量，它是一个`std::nullptr_t`类型的字面量值。
> - 使用`nullptr`比使用传统的`NULL`或`0`更安全，因为它不会与其他整数类型发生歧义，并且提供了明确的空指针含义。

```c++
void foo(int* ptr) {
    if (ptr == nullptr) {
        std::cout << "ptr is a nullptr." << std::endl;
    }
    else {
        std::cout << "ptr is not a nullptr." << std::endl;
    }
}


int main() {
    nullptr_t b = nullptr; // 不赋值而直接调用foo的话会报错: 未初始化. 
    foo(b); // ptr is a nullptr.
    return 0;
}
```

# =default, =delete

前面也提到过, 如果自行定义了一个ctor, 那么编译器就不会再给你一个default ctor. 

如果强制加上=default, 就可以重新获得并使用default ctor.

```c++
class Zoo
{
public:
	Zoo(int il,int i2):d1(il),d2(12){}
	Zoo(const Zoo&)=delete; // copy ctor
	Zoo(Zoo&&)=default; // move ctor. Zoo&&右值引用, 前面也学过了, 后面会细讲.
	Zoo& operator-(const Zoo&)=default; // 赋值操作
	Zoo& operator=(const Zoo&&)=delete; // move assignment
virtual -Zoo() {}
private:
	int dl,d2;
}
```

![[Untitled 831.png]]

这里还是要细想一下, 

```c++
int main() {
    int id = 0;
    auto f = [id]()mutable {
        cout << "id: " << id << endl;
        ++id;
    };
    id = 42;
    f(); // 0
    f(); // 1
    auto g = [&id]()mutable {
        cout << "id: " << id << endl;
        ++id;
    };
    id = 36;
    g(); // 36
    g(); // 37
    f(); // 2
}
```

上面的情况是: id = 0后将id传给了f, 也就是pass by value, 所以后面id = 42后, 也不会影响到f内id为0. 

后面g()传入的是引用, 也就是pass by reference, 所以才可以跟着改动. 

第3个案例是说明必须要有mutable.

可以用lambda做一个排序准则传给unordered containers. 

传给coll构造函数也是必要的, 不然会调用默认构造函数(set())而不用自定义的lambda表达式构造(explicit set(…)). 

lambda导致的报错一般来说非常难以看懂. 

> 在代码中，`std::set<Person, decltype(cmp)> coll();` 会导致一个语法错误，因为这里涉及了一个被称为"most vexing parse"的问题。
> `std::set<Person, decltype(cmp)> coll();` 看起来像是声明了一个名为 `coll` 的函数，该函数返回一个 `std::set<Person, decltype(cmp)>` 类型的对象。然而，这种写法实际上被解析为了一个函数声明，而不是创建一个 `std::set` 对象。
> 
> 这是因为 C++ 中存在一个有趣的规则：当我们在声明一个没有参数的函数时，可以将函数名后面的一对括号视为函数声明的一部分，表示该函数没有参数。所以，`std::set<Person, decltype(cmp)> coll();` 实际上被解释为一个没有参数并返回 `std::set<Person, decltype(cmp)>` 类型对象的函数声明。
> 
> 为了解决这个问题，我们可以使用以下两种方法之一：
> 
> 1. 使用 C++11 的花括号初始化方式：
> ```c++
> std::set<Person, decltype(cmp)> coll{};
> ```
> 2. 使用传统的圆括号初始化方式：
> ```c++
> std::set<Person, decltype(cmp)> coll(cmp);
> ```
> 
> 以上两种写法都可以正确地创建一个 `std::set` 对象并使用 `cmp` 作为其比较函数对象。选择哪种方式取决于个人的编码风格和偏好。

```c++
template<typename... Values> class tuple2;
template<>class tuple2<> {};

template<typename Head, typename... Tail>
class tuple2<Head, Tail...>
    : private tuple2<Tail...>
{
    typedef tuple2<Tail...> inherited;
protected:
    Head m_head; // 必须放在decltype前面, 不然检测不到m_head是什么. 
public:
    tuple2() {}
    tuple2(Head v, Tail... vtail)
        :m_head(v), inherited(vtail...) {

    }
    // typename Head::type head() { return m_head; }
    auto head() -> decltype(m_head) { return m_head; }
    inherited& tail() { return *this; }
};

int main() {
    tuple2<int, string, double> t1{1, "23asd", 2.4};
    auto i = t1.head();
    cout << i << endl;
}
```
