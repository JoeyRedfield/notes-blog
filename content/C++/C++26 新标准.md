# C++26 新标准

C++26 是继 C++11 以来最重要的 C++ 版本。2026 年 3 月 28 日，ISO C++ 委员会（WG21）在伦敦 Croydon 会议上完成了全部技术工作，标准进入国际批准投票（DIS）阶段，预计 2026 年内正式发布为 ISO/IEC 14882:2026。

Herb Sutter 在 Trip Report 中称其为 **"C++11 以来最令人激动的版本"**，并指出 C++26 在编译期反射、内存安全、契约编程和异步模型四个方向上实现了系统性突破。

## 二、四大支柱特性

### 2.1 编译期反射（P2996R13）

**"自模板发明以来 C++ 开发能力的最大提升" —— Herb Sutter**

编译期反射让 C++ 首次能在编译时描述和生成自身，被比喻为"C++ 的十年定义级火箭引擎"。

#### 核心机制：两个新运算符

| 运算符 | 含义 |
|--------|------|
| `^^` | **反射运算符**——将程序实体提升为反射值（类型 `std::meta::info`） |
| `[: ... :]` | **拼接运算符**——将反射值还原为实际源码 |

一切发生在编译期，**零运行时开销、无需 RTTI**。

```cpp
struct Point { int x; int y; };
constexpr auto members = std::meta::nonstatic_data_members_of(^^Point);
// members[0] 是 Point::x 的反射
// members[1] 是 Point::y 的反射
```

#### 纳入 C++26 的反射相关提案（7 篇）

| 提案 | 内容 |
|------|------|
| P2996R13 | 反射核心框架 |
| P1306R5 | 展开语句（Expansion statements） |
| P3096R12 | 函数参数反射 |
| P3293R3 | 拼接基类子对象 |
| P3394R4 | 反射注解 |
| P3491R3 | `define_static_string/object/array` |
| P3560R2 | 反射中的错误处理 |

#### 典型应用场景

**① 枚举转字符串（二十年来呼声最高的特性）**

```cpp
template <typename E>
constexpr std::string_view enum_to_string(E value) {
    std::string_view result = "<unknown>";
    [: expand(std::meta::enumerators_of(^^E)) :] >> [&]<auto e>{
        if (value == [:e:]) result = std::meta::identifier_of(e);
    };
    return result;
}
```

**② 自动序列化（JSON/XML/YAML）**

不再需要手动描述类型——库可以自己遍历数据成员：

```cpp
template <typename T>
std::string to_json(const T& obj) {
    std::string out = "{";
    [: expand(std::meta::nonstatic_data_members_of(^^T)) :] >> [&]<auto m>{
        out += std::format("\"{}\":{},", std::meta::identifier_of(m),
                           to_json(obj.[:m:]));
    };
    out.back() = '}';
    return out;
}
```

**③ Mock、DI、ORM 等框架自动装配**——不再需要 `MOCK_METHOD` 宏和外部代码生成器。

**④ 编译期可变状态**——`define_aggregate` + `consteval` 块实现编译期计数器、映射表和可变变量。

**⑤ 编译期解析外部格式**——配合 `#embed`，可将 JSON 文件在编译期解析为类型安全的 C++ 对象。

#### `std::meta` 关键 API

| 函数 | 用途 |
|------|------|
| `nonstatic_data_members_of` | 枚举非静态数据成员 |
| `enumerators_of` | 枚举枚举值 |
| `identifier_of` | 获取反射实体的名称 |
| `is_complete_type` | 检查类型是否完整 |
| `substitute` | 替换模板参数 |
| `define_aggregate` | 编译期定义不完整类的成员 |
| `reflect_constant` | 反射常量值 |
| `expand(...)` | 展开语句——迭代反射范围 |

### 2.2 内存安全强化

这是 C++26 对安全性的最系统性提升。两个主要变更**仅需重新编译**即可生效，无需修改源代码。

#### 2.2.1 未初始化变量读取不再是 UB（P2795R5）

**由 Thomas Köppe 提出**。定义了新的行为类别——**erroneous behaviour（错误行为）**：

| | C++23 及之前 | C++26 |
|---|---|---|
| 读取未初始化变量 | 未定义行为（UB） | 错误行为（EB），定义良好 |
| 编译器行为 | 任何事都可能发生 | 实现定义的一致值 + 建议诊断 |
| 安全影响 | 严重安全漏洞来源 | 整类漏洞被消除 |

```cpp
void foo() {
    int d;       // d 有错误值
    bar(d);      // 错误行为（行为定义良好，编译器会发出诊断）
}
```

对于性能敏感的代码，可以用 `[[indeterminate]]` 属性选择退回到 C++23 语义：

```cpp
[[indeterminate]] int d;  // 回到 C++23 语义——读取即 UB
```

#### 2.2.2 标准库强化（Hardened Standard Library）

为标准库常用类型提供**边界安全保证**。覆盖类型包括：

`std::vector`、`std::string`、`std::string_view`、`std::span`、`std::mdspan`、`std::array`、`std::optional`、`std::expected`、`std::bitset`、`std::valarray`

**重点**：硬化覆盖常见的**非迭代器操作**（如 `operator[]`、`front()`、`back()`），迭代器边界检查是独立且更难的问题，仍在推进中。

**生产环境数据（Herb Sutter 2025.03 文章引用）**：

| 指标 | 数据 |
|------|------|
| Google 已修复的 Bug | 1,000+ |
| 预计每年防止的 Bug | 1,000—2,000 |
| Segfault 率下降 | 30% |
| 平均性能开销 | ~0.3% |

libc++ 和 MS-STL 均已提供 hardened mode（通过编译选项启用）。

#### 2.2.3 Herb Sutter 的安全三层架构

Herb Sutter 在 2025 年 3 月的文章"Crate-training Tiamat"中描述了 C++ 消除 UB 的三层蓝图：

| 层次 | 内容 | 状态 |
|------|------|------|
| 第一层 | `constexpr`/`consteval` 代码天然无 UB | C++11 起 |
| 第二层 | 未初始化变量 EB + 标准库硬化 | C++26 已采纳 |
| 第三层 | Profiles（Bjarne Stroustrup P3984）、Profiles 框架、RCE 硬化 | 推进中 |

目标：在安全漏洞指标上与现代内存安全语言达到同等水平，消除"不安全"作为放弃 C++ 的理由。

### 2.3 Contracts 契约编程（P2900R14）

C++26 引入了语言级别的契约编程，用关键字替代传统的 `assert` 宏。这是 C++26 最富争议的特性——最终以 **114 票赞成 : 12 票反对 : 3 票弃权** 通过。Bjarne Stroustrup 曾公开反对，称其"声称是最小可行产品，但既不最小也不可行"。

#### 三种契约断言

```cpp
// 1. 前置条件 pre —— 函数体执行前检查
double square_root(double x)
    pre(x >= 0);          // 调用者必须保证 x 非负
{
    return std::sqrt(x);
}

// 2. 后置条件 post —— 函数执行后检查，可引用返回值 r
int clamp(int val, int min, int max)
    pre(min <= max)
    post(r: val < min ? r == min : r == val)   // r 代表返回值
    post(r: val > max ? r == max : r == val);

// 3. contract_assert —— 函数体内任意位置检查
auto* db = getDatabase();
contract_assert(db != nullptr);
```

后置条件支持**返回值标识符**（如 `r`）和**保证复制消除**（无额外拷贝/移动）。

#### 四种求值语义

通过翻译单元级别的编译器标志 `-fcontract-semantic=...` 选择：

| 语义 | 行为 |
|------|------|
| `ignore` | 完全省略检查——零开销 |
| `observe` | 执行检查；失败时调用违规处理器，但**继续执行** |
| `enforce` | 执行检查；失败时调用处理器后 `std::terminate()` |
| `quick_enforce` | 执行检查；失败时直接 `std::terminate()`（跳过处理器，更低开销） |

#### Contracts vs `assert` 宏

| 方面 | `assert` 宏 | P2900 Contract |
|------|------------|----------------|
| 本质 | 宏，编译期文本替换 | 语言关键字，始终合法 C++ |
| ODR 问题 | 混用 NDEBUG 会导致 ODR 违规 | 无 ODR 问题 |
| 函数声明 | 不能出现在声明中 | `pre`/`post` 可放在声明上 |
| 控制粒度 | 仅二值开关（NDEBUG） | 四种语义 |
| 后置条件 | 不支持 | `post` + 命名返回值 |
| 违规处理 | 无标准处理器 | 可定制链接级处理器 |

#### 关键设计原则

- **契约首要原则（Contracts Prime Directive）**：添加或启用契约断言不得改变正确程序的正确性——防止"Heisenbugs"
- **首声明规则**：函数的"首次声明"建立其契约规格；重声明不能添加或更改（只能省略）
- **前置/后置条件可访问私有成员**——它们被视为类作用域的一部分

### 2.4 std::execution 统一异步框架（P2300R10）

C++26 引入了标准的异步编程模型：Sender/Receiver 框架。Herb Sutter 称其为"C++ 的异步模型"，它使结构化并发成为可能——数据竞争在设计层面被消除。

#### 三个核心抽象

| 抽象 | 角色 |
|------|------|
| **Scheduler** | 执行资源的句柄（线程池、GPU 流、I/O 上下文等） |
| **Sender** | 异步工作的描述——可组合、惰性求值、泛化函数 |
| **Receiver** | 多通道回调，接收完成信号（值、错误、取消） |

#### 关键设计原则

- **惰性求值**：Sender 只描述工作；连接 Receiver 并启动后才会执行
- **结构化并发**：Sender 有单一入口和单一出口（类似函数），更安全的组合，避免死锁
- **三通道完成**：`set_value(...)` / `set_error(...)` / `set_stopped()`
- **管道式组合**：`sender | adaptor | adaptor` 风格

#### 核心算法

**Sender 工厂**（从零创建 sender）：
- `just(values...)` —— 创建以给定值完成的 sender
- `just_error(e)` / `just_stopped()` —— 错误/取消通道
- `schedule(scheduler)` —— 在指定执行资源上开始工作

**Sender 适配器**（转换/组合 sender）：
- `then(f)` —— 对值通道应用函数 `f`
- `upon_error(f)` / `upon_stopped(f)` —— 处理错误或取消
- `let_value(f)` / `let_error(f)` / `let_stopped(f)` —— 动态链式调用
- `continue_on(sched)` —— 迁移到不同 scheduler
- `start_on(sched, sender)` —— 在特定 scheduler 上开始
- `bulk(n, f)` —— 批量执行
- `when_all(...)` —— 并发运行多个 sender 并组合结果

**Sender 消费者**（执行工作，在 `std::this_thread` 中）：
- `sync_wait(sender)` —— 阻塞当前线程直到 sender 完成，返回 `std::optional` 元组

#### 代码示例

```cpp
exec::static_thread_pool pool(8);
auto sched = pool.get_scheduler();

// 描述并发工作（尚未执行——全部惰性）
auto fun = [](int i) { return i * i; };
auto work = stdexec::when_all(
    stdexec::starts_on(sched, stdexec::just(0) | stdexec::then(fun)),
    stdexec::starts_on(sched, stdexec::just(1) | stdexec::then(fun)),
    stdexec::starts_on(sched, stdexec::just(2) | stdexec::then(fun))
);

// 实际执行并等待结果
auto [i, j, k] = stdexec::sync_wait(std::move(work)).value();
```

#### 现状与参考实现

目前尚无标准库厂商完整实现 `std::execution`。NVIDIA 维护开源参考实现 **stdexec**（[GitHub: NVIDIA/stdexec](https://github.com/NVIDIA/stdexec)），可在 Compiler Explorer 上使用，也通过 vcpkg 发布。Sutter 承认该特性目前"较难采用"，原因是文档不够完善且生态系统库缺失。

## 六、与 C++11/14/17/20/23 的关系

### 6.1 版本演进脉络

| 版本 | 核心主题 | 本笔记库覆盖情况 |
|------|----------|:---:|
| **C++11** | 移动语义、lambda、auto、智能指针、并发 | [[C++新标准C++11&14|已覆盖]] |
| **C++14** | 泛型 lambda、`make_unique`、变量模板 | [[C++新标准C++11&14|已覆盖]] |
| **C++17** | 结构化绑定、`if constexpr`、`std::optional`、折叠表达式、文件系统 | 未专门覆盖 |
| **C++20** | Concepts、Ranges、协程、Modules、`std::span`、三路比较 | 未专门覆盖 |
| **C++23** | `std::expected`、`std::flat_map/set`、`std::generator`、`std::print`、推导 this | 未专门覆盖 |
| **C++26** | **反射、内存安全、Contracts、Sender/Receiver** | **本笔记** |

### 6.2 C++26 对旧代码的兼容性

- **向后兼容**：绝大多数 C++11/14/17/20/23 代码可直接用 C++26 编译器编译
- **安全免费获得**：内存安全强化（P2795R5 + 标准库硬化）仅需重新编译即可生效
- **移除的废弃特性**：数组比较（P2865R6）现在为 ill-formed
- **C++20 成为默认**：GCC 16 将默认标准从 C++17 升级为 C++20

### 6.3 C++29 展望

C++26 技术工作完成后，委员会采纳了 C++29 的 3 年周期计划。重点方向：

- **进一步的内存安全**——减少 UB，开发 **Safety Profiles**（包括 Bjarne Stroustrup 的 P3984 类型安全 Profile）
- **WebKit 经验报告**（Apple Oliver Hunt P4158R0）：约 400 万行代码使用子集-超集方法硬化，关闭了多个漏洞类别
- **单位与量库**（P3045R7）推进至主库演进组
