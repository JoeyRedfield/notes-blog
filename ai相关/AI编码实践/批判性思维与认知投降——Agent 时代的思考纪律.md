# 批判性思维与认知投降——Agent 时代的思考纪律

> 来源：Addy Osmani，2026-11-03，《Critical thinking when agents do the work》。它讲的不是 agent 怎么编排（那部分见 [[Code Agent Orchestra——多 Agent 编码协作的模式与质量闸门]] 和 [[Loop Engineering]]），而是**人这一层**：当执行和验证都变便宜之后，判断力怎么不被悄悄外包。可以看作 [[AI 工具与注意力管理——从 ADHD 放大器到自律工具]] 的姊妹篇——那篇管注意力去哪了，这篇管判断力去哪了。

**核心命题**：模型越强，批判性思维越不会自动发生——默认没有任何东西会替你做。你可以外包工作、甚至大部分核查，但**外包不了责任**。

## 一、问题：思考的「空隙」消失了

过去，认知和审美加工发生在「问题与答案之间」的那段空隙里；现在这段空隙以秒计。更麻烦的是三件事叠加：

- **明显的错误在变少**：模型越强，「一眼假」的输出越少，多数结果是「写得很好、基本正确，但不值得再看第二眼」
- **一双眼睛面对多双手**：并行跑再多 agent，也只有一双眼睛看输出
- **愉悦感本身就是风险**：快速、舒服、大概率正确的答案，正是最容易让人放松警惕的东西

所以文章的第一条硬结论是：

> You have to build critical thinking into your day, because by default nothing will do it for you.

## 二、三档光谱：offloading → deferral → surrender

| 档位 | 定义 | 结果的状态 | 风险 |
|---|---|---|---|
| **Cognitive offloading** | 把任务交出去，但保留结果的所有权 | 假设 → 验证后成为我的结论 | 无，这是正确姿势 |
| **Deferral** | 工具的输出变成我的新输入，中间没有「我确认过」 | 仍是假设，但我当事实用了 | 能补救：事后补验证 |
| **Cognitive surrender** | AI 的输出悄悄变成我自己的（我署名、我汇报、我维护） | 事实（但未经我确认） | 只在被追问时爆炸 |

漂移之所以危险，是因为每一步都「理性合理」：第一次认真读，第二次扫读，第三次只看骨架，然后被追问某一行时解释不出来。

同一份认知债务有三种形态：

- **个人**：cognitive surrender（文中称由 Wharton 的 Steven Shaw 与 Gideon Nave 提出[^1]）
- **团队**：cognitive debt（Margaret-Anne Storey）——共享系统理论被侵蚀
- **代码**：comprehension debt（Jeremy Twei）——代码库看着干净、测试全绿，直到要改动才发现没人懂了

**最重要的宽慰条款**：不需要维护完整心智模型。Claude Code 团队的做法是按需局部重建——需要理解哪一块，就让模型解释哪一块。接受这份债务的前提是：**知道自己哪里不知道**。

> **唯一判据**：你能不能用（借助 agent 也算）把答案解释出来。说不出，就已经把所有权交出去了。

**低风险场景可以整段外包**。判断标准不是道德，是「错的时候谁承担后果」：作者把挑酒店交给 AI，但投资、孩子职业、产品该做什么这类不交。

### 三档的常见误读（本次 Review 补充）

- **「AI 先说的」不等于 surrender**。所有权看的是「被追问时能不能接住」，不是「想法最初来自谁」。AI 提出 → 你理解、验证、能辩护 → 仍是 offloading。
- **档位不是人的属性，是「模块 × 层次」的局部属性**。同一个人可以在业务规则层 offloading、在 SQL/事务层 deferral、在没碰过的配置层 surrender。健康状态是能画出这条边界。

## 三、六个自问

1. **提问前有没有形成假设？** 哪怕错的也行；没有就先要一个 *blind spot pass*——把你的已知交给模型，让它找你的未知的未知。
2. **是让它帮我思考，还是替我思考？** 两种都行，但要知道自己此刻在哪个模式。
3. **要我这次是错的，必须什么条件成立？** 然后去实际测试。模型自评的置信度，远不如你能跑的检验。
4. **我听过反方吗？** 让多个模型站到反面，自己下判断——更慢，但懂得多得多。
5. **我敢在维护它的人面前押注这个结论吗？** 这是 answerability 的门槛。
6. **我不再练习的是什么？** 可以放弃，但要有意识地放弃。

## 四、验证：绿灯是新的假信号

瓶颈已经从「写代码」移到「确定你是对的」。给 agent 验证手段（e2e 测试、property test、真实应用交互），它就能自己改、跑、读、重试——这是该做的事。

陷阱在于：你会把「**有证据支持结论吗**」降级成「**检查绿了吗**」。

- **测试可能和功能犯同一个错误** → 绿证明的是「代码满足测试」，不是「测试满足需求」
- **绿只证明了一个属性**，而你会不自觉地认为它覆盖了一切
- 规则：**绿灯后先问它证明了什么，再问它没证明什么**

实操五条：

1. **事先把 "verified" 定义清楚**——事后你会为任何结果找理由
2. **完成标准必须可触摸**：测试通过 / 截图 / 日志 / trace，而不是「看起来完成了」
3. **收到完成通知，先看执行的命令和输出，再看摘要**
4. **让新上下文的 subagent 自我批判**；结尾再问一句「我漏了什么」——通常会再冒出 2–3 件事
5. **说不出检查会漏什么，就要真审查，而不是快速批准**

### 案例：一个「默认值」测试的四种盲区

假设 AI 给餐品 insert 接口加了默认值 `餐品类型 = 普通`，并附一个跑绿的 JUnit。这个绿**没有**证明：

| 没证明什么 | 原因 |
|---|---|
| 印花餐品那条路径 | 绿只覆盖测试构造的那一条 |
| 真的写进了数据库 | 如果 Mapper 被 mock，绿的是桩不是系统 |
| 该拒绝的有没有被拒绝 | 「印花不能进普通组」是禁止型规则，只能靠负向用例验证 |
| 默认值该不该存在 | 测试和实现同源，默认值错了照样绿 |

## 五、读决定，不读摘要

600 行的 PR：变量名正常、测试全绿，中间可能藏着一个事务边界的顺序变化。你审的其实是「你预期会看到的东西」。

- **读 diff 要像它不是 AI 写的**，然后看 diff 之外**它替你做的决定**：默认值、范围外的取舍、需求冲突时它重解释了哪一条
- 要求交付时附一份 **Decisions & Assumptions**，然后自测：随机挑几行问「这行干嘛的」；文档合上凭记忆复述主要论证
- **Orchestration tax**：产出超过你愿意署名的量时，你不再是在审查，而是在希望。积压时再开一个 session 没用——收紧检查或放慢
- **Intent debt**：含糊的需求以前会被人挑战，现在 agent 会替你填满并交回看起来完成的东西。这份债只有你能还
  - **prompt 是你对问题理解的镜子**：说不清楚，可能意味着没想清楚
  - 第二轮纠正还没到位，就重写 prompt，而不是继续微调
  - 可以让 agent 反过来采访你；如果一次会话结束，你自己的心智模型被磨清楚了，那才是成功
- **摘要污染**：agent 之间互相传摘要，第三个 agent 就没读过原文——这和 ingest 时用摘要代替源材料是同一个病
- **品味复利**：不达标的东西，把「为什么不达标」写进 config / hook / test

## 六、责任不可外包

「模型以后会比我更准」这个反问，文章的回答是：

- **总得有人对上线的东西负责**。可以外包工作、外包审计，但外包不了 accountability
- **信多少本身是判断**，而模型错的东西一直在变，要保持校准就只能看
- **监督悖论**（Anthropic 研究）：监督 Claude 需要的，正是可能因过度使用 AI 而萎缩的编码技能
- 更好的模型解决不了的四个问题：**建什么、为什么值得、影响谁、愿意牺牲什么**

> **不署名就不发布**：AI 可以更快产出，但如果我不愿意把输出归到自己名下，我就不发。

## 七、日常实践

- **每周**：不用 agent 写一段真代码，或做一件「忘了会很难受」的事（calibration exercise，不是道德要求）
- **每月**：写下「我已经不再做的是什么」，然后决定哪些可以接受
- 常问：**如果 AI 不存在，我会有多迷失？**
- 超出理解就去学——遇到不认识的术语，别只停在一行解释
- **检查机器是真实工作**，要排进日程表，而不是假装它免费

## 八、与我的工作流的映射（2026-11-04 交互 Review 结论）

1. **[[三角循环——AI编码核心概念内化记录|三角循环]] 加三道闸**：① 假设先行（先写下我认为会怎样）② 绿后反问（证明了什么、没证明什么）③ 交付附 `Decisions & Assumptions`。
2. **前端是标注过的 deferral 区**：Vue/TS 不熟，不假装审过；改用行为证据（验收路径、空态/错误态截图、diff 翻译）来审，并给一个最低可读预算。
3. **餐品模块补一层**：把「分类为什么有意义」（业务语义）和「约束 enforcement 在哪」（外键 / 服务端校验 / 前端数据来源）分开，后者要去找代码和硬件确认。
4. **Ingest tax**：产出笔记的量超过我能背书的量时，我不是在学习，是在归档。检验方式——合上笔记，凭记忆写出主要论证。
5. **每周/每月动作**：每周一次无 agent 写码；每月一次「我不再做的是什么」清单。
